## 1. 背景与目标

## 2. 已拍板结论（用户拍板 + jury 共识）

### 2.1 content 合并

- **文件命名：`content.tex`（LaTeX 路径）/ `content.md`（PDF 路径）**——用户拍板（专家 C 建议：合并后含附录，"body" 名不副实是语义陷阱）。manifest 字段 `files.content`（`#[serde(alias="body", default)]` 兼容读旧 manifest）。
- **合并 = 无损拼接**：`content.tex = body.tex + "\n\n" + appendix.tex`，`\appendix` 命令留在文中（appendix 切片本就始于 `\appendix`，拼接即还原原文）。LLM 靠章节标题区分正文/附录。
- **不截断哲学**：DeepSeek v4 context = 1M tokens，截断上限已从 120k 提到 2M 字符（head+tail 保留两端）——正常文档（含几十页技术报告）全量通过。**合并顺带修复双文件各自 2M 截断可能合计超窗的潜在 bug**。
- **分块价值重估**：Agent 消费的是 deep_summary（LLM 生成时通过标题结构区分正文/附录），body/appendix 文件级分块对 PDF 路径无意义 → **PDF 论文不拆，full.md 整体落 content.md**；LaTeX 路径合并为 content.tex 后同样不再有文件级分块（appendix 概念退化为计算视图）。

### 2.2 PDF 输入路径

- 命令：`paper ingest-pdf <file.pdf> [--id <自定义ID>] [--title <自定义标题>]`
- MinerU 精准 API（vlm 模型）：`file-urls/batch` 预签名上传 → PUT → 自动解析 → `extract-results/batch` 轮询 → zip（full.md + content_list.json）→ full.md 落 `content.md`，源 PDF 存论文目录（`files.pdf`）
- **自动摘要默认开**：PDF 解析完自动生成 brief + deep——**与 download 的后续流程完全相同，唯一区别是 source 标记**（用户明确："除了来源不一样，我希望 Archive 和 PDF 后面的流程完全相同"）
- 表格：MinerU 转录的 HTML（实测 8/8 数字准确；有误差风险，deep_summary 标注来源）

### 2.3 身份体系（全局 ID 设计——用户"最底层标识符"关切）

**结论（3:0 专家共识 + 用户拍板）：统一"抽象"不统一"句法"，hash 是 PDF 身份的主路径。**

- **arXiv 论文：arxiv_id 原样保留**（`2501.12948`）——它是权威全局 ID（中央签发、全宇宙唯一、跨版本稳定），加 `arxiv:` 前缀是纯成本（零信息增益 + 冻结契约 churn）。不替换、不包装。
- **PDF 论文：内容 hash 是身份本体**（不是兜底）——真实场景 90%+ PDF 提不出任何 ID（非 arXiv、技术报告、内部文档），hash 就是正式身份。
  - `hash = sha256(文件字节) 前 12 hex`（48 位，碰撞概率≈零；12 vs 16 未决，见 U2）
  - **稳定的是"字节"不是"论文"**——同论文不同渠道/版本 PDF → hash 不同 → 不同条目。这是 hash 身份的本质，接受为合法状态。
  - 文件夹名：`pdf_<hash12>_<slug>`（slug = 文件名清洗，可读 + 去重提示信号）
  - 能提取 arXiv ID（PDF metadata / `arXiv:` 前缀，尽力而为，不做复杂工程）→ 用 ID 惯例
- **身份与目录名正式解耦**：现有实现已是 manifest-first + legacy 目录回退双通道（真实 37 篇目录全是 legacy `{id}_{title}` 形态、35/37 无 manifest）——方案 C（身份在 manifest，目录名是物理细节）**已事实上运行**，本次正式声明并写进架构文档。
- **manifest**：顶层 `arxiv_id` 可空（PDF 论文为空）+ `source: "arxiv"|"pdf"`（default "arxiv"，旧 manifest 无损读入）+ `files.content`/`files.pdf`。
- **JSON 信封**：`arxiv_id` 字段对 PDF 论文输出 `pdf_<hash12>`（未决见 U3）。

### 2.4 迁移与契约

- **schema 1→2，lazy 迁移**（沿 lazy_migrate_brief 先例）：写路径触达时 `content.tex = body.tex + appendix.tex`，删旧文件，更新 manifest；读路径回退（旧文件夹无 content 字段 → 回退 body+appendix 现行逻辑）。不加迁移命令。
- **迁移顺序（崩溃一致性，C 专家要求）**：写 content.tex（tmp+rename 原子）→ 先原子保存 manifest（指向 content.tex）→ 最后删 body.tex/appendix.tex（孤儿文件无害）。**重入条件 = content.tex 存在性**（不是"body.tex 含 \appendix"——skill 里旧守卫与改名设计矛盾，实施前必须先改 skill）。
- **preview -v appendix 保留为计算视图**（按 `\appendix` / `## Appendix` 切片；PDF 侧切片模式需真实 MinerU 输出验证）。
- **冻结面不动**：退出码 0-8/130、JSON 信封、错误 kind 枚举、命令名全部不变。0.12.0 单版捆绑。
- **版本号**：0.12.0（破坏性：manifest schema、文件结构）。crates.io 未发布过，无外部用户契约义务。

## 3. 评审发现的关键修订项（0.12.0 实施必须包含）

来自大改方案 jury review（deleg_a98b1417，3:0），全部是实施规格：

- **R1. 空 arxiv_id 硬拒绝**：`download_source("")` 会删整个下载缓存（id_dir_name="" → downloads 根目录 → remove_dir_all）。`download_source`/`process_pending_paper` 入口对空 ID 直接报错。**pending 过滤必须排除 source="pdf"**（部分失败的 PDF 论文报 failed/提示重跑 ingest-pdf，不进 arXiv 下载管线）。
- **R2. process_pending_paper 成功判定**：`Ok(out_dir.join("body.tex").exists())` 在合并后恒 false → **所有新下载报 FAILED + 武装 24h cooldown**（比 PDF 论文更严重——影响所有论文）。改 manifest 驱动（content.tex 或 body.tex 任一存在）。
- **R3. redownload 按 source 分支**：backup 清单加 content.* + 源 PDF；pdf-source 用存的 PDF 重跑 MinerU（幂等）或直接拒绝；空 arxiv_id 拒绝。**否则 PDF 论文 redownload = 永久数据丢失**。
- **R4. scan_manifest 探测矩阵**：content.tex > content.md > body.tex 探测优先级 + prev.files 保留策略（pdf/title/source 等显式继承）——**source 不加进 prev 继承清单会被写路径静默清零成 "arxiv"**。
- **R5. 全触点清单**：resolve_view_file（返回 &'static str 需改签名，preview -v body 是默认视图也坏）、cmd_strip、cmd_info --json files 键（body.tex/appendix.tex → 全 0）、chat /context body（静默吞错）、cmd_pdf（空 ID fallback 拼垃圾 URL）、build_user1（body.tex 回退 content）、extract_tabular（扫单文件 + HTML table）、find_papers_by_id("")（前缀匹配全库）。
- **R6. 身份信任边界**：PDF 提取只信 metadata / `arXiv:` 前缀；正文裸正则 `\d{4}\.\d{4,5}` 会 citation leak（非 arXiv 论文引用 arXiv 文献即被伪 ID 污染）——**正文匹配结果需 --id 确认或弃用**。用户拍板：尽力而为，提不出来留空。
- **R7. 混合源**：`download <同ID>` 撞已有 source=pdf 目录 → 双内容文件并存——download 遇 source=pdf 目录拒绝并给明确错误。
- **R8. arxivcat_extension 同步**（活体消费方）：SKILL.md + extract_tables.py 硬编码 body.tex/appendix.tex → 合并后静默失效、附录表格丢失。同 release 更新扩展（改读 content/manifest）或显式弃用。
- **R9. 降级故事**：0.11.x 二进制读 schema-2 工作区 → files.body 缺失 + body.tex 已删 → has_body=false → **全量重下载**。**用户已拍板接受此代价**，release notes 必须写明。
- **R10. SUMMARY_SYSTEM 中性化**：现为 "You read arXiv paper LaTeX source"——PDF 论文在此撒谎 prompt 下生成摘要。同版顺手改（合并已使 build_user1 字节变化、round-2 缓存本就要失效一次，零额外成本）。
- **R11. ingest-pdf 并发**：两个并发 ingest 同 PDF → 同 hash 目录竞争写——按 hash 复用 DownloadLock 或 per-dir flock。

## 4. 悬而未决的问题与难点（实施前需拍板/验证）

### U1. hash 稳定性（本质难点，已接受为设计约束）
hash 稳定的是"文件字节"不是"论文"——同论文不同渠道/版本 PDF 会成为不同条目。已接受为 hash 身份的本质（PDF 无语义 ID 可依）。缓解：文件名 slug 去重提示（ingest 时检测已有相似标题/文件名论文 → 警告）。**是否做"标题语义去重合并"功能**（0.13+ 的 ID 中心）未决。

### U2. hash 长度：12 vs 16 hex
12 hex = 48 位（碰撞概率 ≈ 2^-48，实际零风险）；16 hex = 64 位（绝对安全但更长）。**倾向 12**（目录名长度 vs 理论碰撞，48 位足够）。

### U3. JSON 信封的 arxiv_id 字段（PDF 论文）
选项：① 输出 `pdf_<hash12>`（Agent 有稳定身份可引用）② 输出空字符串 + 新增 `pdf_id` 字段（语义清晰但破契约形状）③ 输出 `pdf_<hash12>` 到新字段。**倾向 ①**（Agent 拿它当 ID 用，信封形状不变）。

### U4. arxivcat_extension 的命运
活体消费方（SKILL.md + extract_tables.py 读 body.tex/appendix.tex）。选项：① 同 release 更新（改读 manifest files.content）② 显式弃用（归档，deep_summary 由 CLI 管线接管）。**倾向 ①**（它承载 extract_tables.py 表格处理逻辑，MinerU 表格集成前仍有用）。

### U5. PDF 论文的 deep_summary 表格段格式不一致
LaTeX 路径 = ```` ```latex ```` tabular cp（零转录）；PDF 路径 = ```html（MinerU 转录）。Agent 消费者会看到格式不一致——**必须文档化**（cli.md + release notes）。若 `extra_formats:["latex"]` 实测能把表格 tabular 化（MinerU TODO），可部分恢复"零转录"哲学。

### U6. PDF 侧 appendix 切片模式
MinerU 输出附录标题形态多样（`## Appendix A` / `# Appendix` / `## Supplementary` / 无标题）——preview -v appendix 与 chat appendix 上下文的切片正则需**拿真实 MinerU 输出验证**，无附录 PDF 返回空/提示。

### U7. 迁移触发面
"写路径首次 refresh 即迁移"——但 `cmd_note` 只写 note.txt 不调 refresh_manifest（manifest 注释说 note 是写路径，实际不刷新）→ 只编辑 note 的旧文件夹永不迁移。选项：① 让 note 也触发 ② 接受并文档化。

### U8. LaTeX 与 PDF 路径的 content 语义不对称
LaTeX 提取删 `\bibliography`、body 止于附录前 → content.tex **不含参考文献**；MinerU full.md **含 References** → 两路径喂给 LLM 的上下文不同。选项：① 文档化（接受不对称）② PDF 路径裁剪对齐。

### U9. 无 ID 论文的 list/chat/错误文案
list 排序（空 id 恒排最后）、download-all skipped JSON 的 `id:""` 无辨识度、ambiguous 错误文案"Use the full arXiv ID"对 PDF 论文是错误指引——需按 hash 身份调整。

### U10. 旧二进制回写 manifest（0.11.x 写新工作区）
0.11.x 的 refresh_manifest 会把 schema-2 重写为 schema-1（files.body=None、files.content 被丢弃）→ 升级回来无 content 字段 + body.tex 已删 → 重下循环。已接受降级代价（R9）但**双写别名（files.body 也写 "content.tex"）是零成本防御**——实施时决定。

### U11. MinerU token 命令面
config.rs 只有 deepseek_api_key，`token set/status/validate` 是 DeepSeek 专用——MinerU token 落哪里（新 key 名 + env + 子命令扩展）未决。

### U12. ingest-pdf 失败残留
ingest 失败（MinerU task failed/轮询超时/zip 破损）是否写 manifest + cooldown——不写则残留空 hash 目录对 list 不可见（Paper::from_folder 无 manifest 且目录非数字下划线格式 → 不可见孤儿）。

### U13. workspace scan 与 ingest-pdf 双入口语义
`scan_workspace_pdfs` 仍给有 ID 的根目录 PDF 建文件夹（pending → LaTeX 下载）、无 ID 静默跳过——保留原语义还是改走 MinerU？未决。

## 6. 决策历史（为什么这样设计）

1. **body/appendix 合并**（用户拍板 + jury-ask 3:0）：Agent 消费 deep_summary，body/appendix 只是 LLM 中间输入；LLM 靠标题区分正文/附录；2M 截断后无挤压；PDF 论文"无痛"落地的前提。
2. **content 命名**（用户拍板，专家 C 建议）：合并后含附录，"body" 名不副实是语义陷阱；代价 = 旧二进制降级全量重下（用户接受）。
3. **PDF 输入**（用户拍板方向 + MinerU 实测 8/8）：新入口，MinerU presigned 上传解决"不支持上传"；自动摘要默认开，流程与 download 全同。
4. **身份体系**（用户"最底层标识符"关切 + jury-ask 3:0）：统一抽象不统一句法；arXiv ID 原样（权威 ID 无替换理由）；hash 是 PDF 身份主路径（90%+ PDF 无 ID）；身份与目录名正式解耦（已事实上运行）。
5. **arxiv_id 可空**（用户拍板）：PDF 论文无 ID 是常态，可空 + hash 身份。
6. **不截断**（用户拍板）：DeepSeek v4 = 1M context，120k 截断是旧时代保守设置；2M 字符上限 + head+tail。
